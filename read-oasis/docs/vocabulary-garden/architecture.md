# Vocabulary Garden — Architecture

The Vocabulary Garden is a **companion learning area** inside Read Oasis. It does
not replace reading; it grows from the words a child meets in books. It is
powered by a private Cambridge YLE 2025 lexicon that is treated as an **immutable
source** and never mutated at runtime.

## Three data layers

| Layer | Name | Location | Mutability | Owner |
|-------|------|----------|------------|-------|
| **A** | Source lexicon | `ref_docs/cambridge-yle-word-list-2025/lexicon.json` | Immutable (pinned by sha256 in `source_manifest.json`) | Editorial ingest only |
| **B** | Read Oasis enrichment | `content/vocabulary/entries/{a..z}.json` + `manifest.json` | Versioned, regenerated by tooling; original teaching content only | Editors |
| **C** | Child learning progress | `localStorage` (`vocab_progress` inside the progress store) | Per-device, evidence-based | The child's device |

**Layer A is never written by the app or by enrichment tooling.** Enrichment
entries only *reference* a source record by `word_id` and pin the source PDF
sha256. The validator proves this (Gate 3) and a Python test proves the source
file is byte-identical before/after a build (`test_enrichment_never_mutates_source_lexicon`).

## Layer B — enrichment (fail-closed dispositions)

`tools/vocab/build_enrichment.py` produces **one entry per eligible source
record**, each with exactly one explicit `status` (disposition):

| Disposition | Meaning | Appears in child garden? |
|-------------|---------|--------------------------|
| `editorially_approved` | Hand-authored, sense-verified original teaching content | **Yes** |
| `published` | Approved + parent-confirmed (future publish step) | **Yes** |
| `draft` | Eligible, awaiting original authoring + review | No |
| `blocked_source_review` | Source record quarantined / `review_required` | No |
| `not_teachable_as_standalone` | Proper name / title | No |
| `blocked_ambiguous` | Multiple eligible senses, unresolved | No |
| `excluded_with_reason` | Deliberately excluded | No |

Current committed counts (verified): **1403 entries** —
`blocked_source_review: 77`, `draft: 1259`, `editorially_approved: 14`,
`not_teachable_as_standalone: 53`. Only the **14 hand-authored** senses carry
teaching content; everything else is honestly empty. Nothing is fabricated as
"reviewed".

Entries are sharded A–Z so the child runtime loads only the letter it needs.

## Mapping (book page → approved word)

`tools/vocab/build_mappings.py` matches each book-page vocabulary surface form
against **approved enrichment entries only**. A mapping is auto-approved **only
when exactly one eligible approved candidate exists**; anything ambiguous goes to
`ambiguous_queue.json` and is never auto-mapped. Each approved mapping is pinned
to `book_id + book_revision + page_id + surface_form + source_pdf_sha256 +
enrichment_revision`, so changing a book's text or bumping a revision invalidates
the mapping (fail-closed).

Current committed mapping result (verified): 92 occurrences, **14 approved, 0
ambiguous, 78 unmapped**, 10/43 books with ≥1 mapping.

## Layer C — child progress (evidence, not a boolean)

Progress lives in the existing progress store, bumped to `STORE_VERSION = 2`. A
word is **never** marked "mastered" from one lucky tap. Instead we record
discrete **evidence** events and derive a support level:

- Evidence types: `encountered_in_book`, `listened`, `recognized_in_context`,
  `recognized_from_audio`, `recalled_without_choices`,
  `pronounced_self_listened`, `used_in_new_context`, `parent_reviewed`.
- Derived support level (`vocabSupportLevel`): `not_yet` → `with_support` →
  `independent` → `used_in_new_context`.
- Every event is **idempotent** via a `dedupKey` (repeat / refresh / double-click
  cannot double-count). The `vocab_ledger` is the source of truth; per-word
  counts are rebuilt from the deduplicated ledger, so **offline sync / re-import
  never double-counts** (`mergeStores`).

## Runtime & offline

- Kid app: `src/kid-app.mjs` routes `view: 'garden'` to
  `src/vocab-garden.mjs`. A library entry button appears **only if** the
  vocabulary manifest reports ≥1 approved/published entry; otherwise reading is
  unaffected.
- Service worker (`sw.js`): the shell now includes `src/vocab-garden.mjs`, and
  install precaches **only public-safe** vocabulary artifacts — `manifest.json`,
  approved letter shards, and `book-page-mappings.json`. It **never** caches the
  private source lexicon, raw occurrences, review queues, or editorial notes
  (those never ship in the app directory at all).

## Safety invariants (enforced by `tools/vocab/validate_vocab.py`)

1. Every source record → exactly one entry with exactly one valid disposition.
2. No quarantined / `review_required` record is approved or published.
3. Every entry + the manifest pin the immutable source PDF sha256.
4. Proper names / titles are `not_teachable_as_standalone`.
5. Only approved/published entries carry teaching content.
6. Mappings reference only approved entries and pin book/page/hash/revision.
7. Manifest `disposition_counts` equal the recomputed counts.

All seven gates currently **PASS** (exit 0).
